배포를 준비하고 진행하라. `docs/DEPLOY.md`의 런북을 따른다.

## 1. 배포 전 게이트 — 모두 통과해야 진행

| 게이트 | 확인 방법 |
|--------|----------|
| 전체 검증 통과 | 배포 대상 브랜치에서 `bash scripts/verify.sh full` |
| CI 그린 | 대상 브랜치의 최신 CI 실행 결과 |
| 보안 점검 완료 | `docs/security/` 최신 리포트에 Critical/High 없음 (또는 수용 리스크로 사용자 서명) |
| 코드 리뷰 완료 | 배포 대상에 머지되지 않은 PR 없음 |
| 롤백 방법 확정 | DEPLOY.md 롤백 섹션이 현재 배포에 유효한지 확인 |

하나라도 실패하면 배포를 중단하고 사용자에게 보고하라.

## 2. 배포 실행

- `docs/DEPLOY.md`의 절차를 순서대로 따른다. 런북에 없는 임의 조치를 하지 마라.
- 수동 단계(서버 접속, 파일 업로드, 운영 승인 등)는 사용자에게 안내하고 완료 확인을 받은 뒤 다음으로 진행한다.
- 각 단계의 실행 결과를 기록한다.

## 3. 배포 후 확인

- DEPLOY.md의 스모크 테스트 항목을 실행/안내한다.
- 결과를 `docs/releases/{버전 또는 날짜}.md`로 기록한다: 배포 내용 요약, 배포 시각, 확인 결과, 특이사항.
- 실패 시 즉시 DEPLOY.md의 롤백 절차를 안내한다.

## 금지사항

- 게이트를 건너뛰지 마라. 이유: 게이트는 사람이 급할 때를 위해 존재한다.
- 운영 환경에서 런북에 없는 명령을 실행하지 마라. 필요하면 먼저 런북을 갱신하고 사용자 승인을 받아라.
