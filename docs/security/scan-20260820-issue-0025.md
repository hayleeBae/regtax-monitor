## 점검했으나 이상 없음

**자동 점검**
- 시크릿 패턴 스캔(`verify.sh security`의 `git grep` api_key/secret/password/token=…): 실행됨, 하드코딩 시크릿 0건.

**입력 처리**
- `/apply` DB 라우팅 입력은 `row.law_id`·`row.article_no`(DB `LawChange` 행에서, 요청 본문 직접 아님). `change_id`는 FastAPI가 검증하는 int 경로 파라미터.
- SQL: 문자열 연결 없음. 기존 SQLAlchemy ORM 쿼리 그대로. `DbDataRegistry.match`는 순수 문자열 비교(`==`, `in`) — 인젝션 표면 없음.
- 경로 조작: 사용자 입력이 파일 경로에 들어가는 신규 코드 없음.

**인증/인가**
- 신규 엔드포인트 없음(`/apply`에 분기 추가). 인증 로직 변경 없음.
- IDOR/조직 스코프: `law_id`/`article_no`는 엔드포인트가 이미 로드한 동일 `LawChange` 행에서 파생 — 신규 교차 접근 표면 없음(내부 단일 테넌트 도구).
- localhost/개발 인증 우회 코드 추가 없음.

**데이터 보호**
- 응답 필드(item_label·law_name·article·before·after·guidance): 일반화 라벨 + 법령 조문값 + 큐레이션 안내문만. **DB 스키마 원문(테이블/컬럼명)·PII·시크릿 없음.**
- `DbUpdateGuidance`에 `db_hint` 필드 **미포함** — DB 구조 힌트는 응답으로 나가지 않음(`asdict` 직렬화 6필드 한정).
- `domains.json` `db_items`는 빈 배열(스키마만) — 커밋 산출물에 스키마 원문 없음. registry.py 주석이 스키마 원문 금지를 명시.
- 로그: `audit.record(POLICY_DECIDED, {decision, reason_codes, policy_version})` — 민감 데이터 없음.

**설정/의존성**
- CORS/쿠키/TLS 설정 변경 없음. `verify=False`·`NODE_TLS_REJECT_UNAUTHORIZED=0` 등 없음.
- 디버그 모드·개발용 잔존 코드 없음.

## 수용된 리스크 (사용자 확인 필요)
- **`/apply` 등 내부 엔드포인트에 요청 단위 인증 없음** — 이번 변경이 만든 것이 아니라 **기존 내부 도구 설계**(사람 승인 게이트가 별도 보호). 이번 PR 범위 밖. 향후 운영 노출 시 별도 이슈로 인증 게이트 검토 권고.
- **`_parse_db_items`가 `item["law_id"]` 등 필수 키를 직접 인덱싱** — 잘못된 `domains.json`이면 KeyError. 보안이 아니라 설정 무결성 견고성 이슈. domains.json은 신뢰된 repo 파일이라 위험 낮음. 담당자가 `db_items` 작성 시 스키마 준수 필요.
