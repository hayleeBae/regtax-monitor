## 점검했으나 이상 없음

- **SQL 인젝션**: `SqlAlchemyDecisionContextLookup`의 두 쿼리는 SQLAlchemy ORM이며 `Mapping.article_id == self.article_id`, `MappingDecision.mapping_id.in_(mapping_ids)` 모두 파라미터 바인딩. 문자열 연결 쿼리·raw SQL 신규 추가 0건.
- **입력 검증 / 신뢰 경계**: 신규 엔드포인트 없음. rerank가 받는 `article_id`(`f"{law_id}:{article_no}"`)와 `change_type`은 **DB의 `LawChange` 행에서 유래**하며 요청 본문·쿼리 파라미터에서 직접 오지 않는다. `DecisionContext.__post_init__`가 `rejection_count` 음수와 잘못된 `state` 타입을 거부.
- **경로 조작**: 매핑 `path`는 `CandidateLocation`이 검증(빈 값·절대경로·`../` 상위 탈출 거부)하고, `reranking_lookup._dedup_key`는 `ValueError`를 삼켜 해당 매핑만 건너뛴다. rerank 경로에서 파일을 열거나 쓰지 않는다.
- **YAML 역직렬화**: `decision_fixtures.load_decision_fixtures`는 `yaml.safe_load` 사용(임의 객체 생성 불가). 입력 경로는 `--decisions` CLI 인자로 운영자가 직접 지정하는 로컬 개발 도구이며 웹 노출면이 아니다. root가 mapping이 아니거나 `decisions`가 리스트가 아니면 `ValueError`.
- **인증/인가·IDOR**: 신규 엔드포인트·권한 분기 0건. rerank 조회 범위는 요청된 `change_id`에서 파생된 단일 `article_id`로 한정되어 기존 `map` 엔드포인트의 조회 범위를 넓히지 않는다. 앱 전체 무인증 태세는 #0015 리포트의 Low #1과 동일하며 이번 변경이 노출면을 추가하지 않는다.
- **코드 반출 금지 (CLAUDE.md CRITICAL)**: `DecisionContext`가 나르는 값은 article_id·change_type·state·reason_code·카운트·불리언 플래그뿐 — **코드 본문·스니펫 없음**. 응답에 추가된 키는 `rerank_version`(고정 문자열 `verified-rerank-v1`) 하나. 외부 API 전송 경로 신규 추가 0건이며 `LLM_BACKEND=claude` 경로 무변경.
- **승인 게이트 우회 금지 (CLAUDE.md CRITICAL)**: patch 자동 적용 경로 미추가. rerank는 후보 **순위**만 바꾸며 `apply`/승인 흐름과 골든 테스트 경로는 무변경.
- **결정 이력 무결성**: `reranking_lookup`은 읽기 전용 — INSERT/UPDATE/DELETE 0건. 검색 중 자동 stale 이벤트를 만들지 않는다(스펙 §8 준수). #0015 append-only 규약 유지.
- **로깅·개인정보**: 이번 diff에 `print`/`logging`/`logger` 추가 0건. 주민번호·계좌·급여 등 개인정보를 다루거나 로그에 남기는 경로 없음.
- **시크릿·설정**: 하드코딩 시크릿 0건, 커밋된 `.env` 없음. 신규 설정은 `Settings.verified_reranking_enabled: bool = True` 하나이며 `.env.example`에 문서화. CORS·쿠키 플래그·디버그 모드·TLS 무력화(`verify=False`, `NODE_TLS_REJECT_UNAUTHORIZED`) 변경 0건.
- **커밋된 fixture 내용**: `evaluation/fixtures/decisions/core_decisions.yaml`은 합성 데이터로, 참조 경로가 `tax/TaxConstants.java`·`salary/HrConstants.java`(mock 평가 fixture)뿐이며 실제 eHR 경로·컬럼코드·내부 파생물을 포함하지 않는다. CLAUDE.md의 캐시 파일 커밋 금지 규칙에 저촉되지 않는다.
- **의존성**: `requirements.txt`/`requirements-dev.txt` 무변경. `yaml`·SQLAlchemy 등 기존 스택만 사용.
- **자원 소모**: rerank가 `final_top_k` 절단 전에 실행되지만 DB 질의는 후보 수와 무관하게 article_id당 **2회로 고정**(N+1 없음). 후보 수 자체는 provider `top_k`로 이미 제한된다.

## 점검 불가

- **운영 환경 실데이터 기준 동작**: 회사 eHR repo·실제 `mapping` 테이블에서의 조회량과 예외 발생 양상은 집(mock) 환경에서 확인할 수 없다. 발견 #1의 실제 노출 문자열도 회사 환경에서 재확인이 필요하다.
