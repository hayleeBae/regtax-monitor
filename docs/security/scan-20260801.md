## 점검했으나 이상 없음
- **SQL 인젝션**: 결정 저장은 SQLAlchemy ORM(파라미터 바인딩). `_backfill_legacy_mapping_decisions`의 raw SQL은 `text()` + `:created_at` 파라미터 바인딩이며 나머지는 정적 SQL(`m.verified = 1`, 값 리터럴) — 사용자 입력 문자열 연결 없음.
- **입력 검증**: `decision`은 `MappingDecisionType` enum 검증(미지 값 → 422), `reason_code`는 `allowed_reason_codes()` allowlist 검증(불일치 → 422). `mapping_id` 없으면 404.
- **경로 조작**: 파일 경로에 사용자 입력이 들어가는 신규 경로 없음. `mapping_id`는 int path param, `db.get(Mapping, ...)`에만 사용.
- **데이터 보호(로그/평문)**: 이번 diff에 로깅 추가 없음(`print/log` 패턴 0건). 개인정보(주민번호·계좌·급여)를 다루거나 로그에 남기는 경로 없음. decision 응답은 해시·사유·actor만 반환, 대상 코드 본문 미노출.
- **시크릿/설정**: 하드코딩 시크릿·커밋된 .env 없음. CORS·쿠키 플래그·디버그 모드·TLS 무력화(`verify=False`, `NODE_TLS_REJECT_UNAUTHORIZED`) 변경 없음.
- **코드 반출 금지(CLAUDE.md CRITICAL)**: decision 테이블/응답에 코드 본문 없음 — 해시만. 외부 전송 경로 신규 추가 없음.
- **승인 게이트(CLAUDE.md CRITICAL)**: patch 자동 적용 경로 미추가. `apply` 흐름 불변.
- **append-only 무결성**: repository `update`은 `NotImplementedError`, 수정·삭제 API 없음 → 이력 위·변조 표면 최소화.
- **의존성**: 신규 런타임 의존성 없음. pip-audit clean(1 문서화 ignore).

## 수용된 리스크 (사용자 확인 필요)
- **#1 무인증 + actor 자기신고**: 로컬 단일 담당자 운영 전제로 수용. ADR-008에 명시된 한계와 동일. 회사 다중 사용자 환경으로 확장 시 재평가 필요.
- **#2 `reason_text` 내용 미검사**: 담당자 자유 입력 신뢰로 수용.

## 게이트
- **Critical/High 없음 → 배포 게이트 통과.** Low 2건은 모두 기존 보안 태세와 동일한 수용 항목으로, 이번 변경이 신규 취약점을 도입하지 않음.
