## 점검했으나 이상 없음

- **경로 조작(traversal)**: `_check_relative_path` 가 `repository.path`·`scope.relevant_paths`·`excluded_paths`·`expected_replacements[].path` 전부에 대해 절대경로와 `..` 구성요소를 거부한다. 빌더의 `ensure_within()` 은 삭제 대상을 resolve 후 출력 루트 **하위**임을 확인하고 루트 자신도 거부하며, 심볼릭 링크로 루트 밖을 가리키는 경우까지 막는다(`shutil.rmtree` 직전 호출).
- **임의 경로 삭제 방지**: 빌드 스크립트 CLI 에 출력 경로 옵션이 **없다**(`--case`/`--quiet` 만). 출력 루트는 모듈 상수로 고정. `--case` 값은 `discover_cases()` 결과 목록과 대조되고 케이스 이름은 `^[a-z][a-z0-9_]*$` 로 제한된다 — 인자를 통한 경로 주입 불가.
- **명령 주입**: 모든 git 호출이 `shell=False` + 인자 배열 + `timeout=120s` 단일 래퍼(`_run_git`)를 통한다(스펙 §5). 문자열 조립 명령 없음.
- **git revision 인자 주입**: `_check_revision` 이 `-` 로 시작하는 값(`--upload-pack=...`)을 우선 거부하고, `..`(revision range) 거부, 나머지는 `[A-Za-z0-9._/-]` 문자 집합으로 제한한다. #0018 이 이 값을 git 에 넘기므로 입구 차단이 유효하다.
- **환경 오염·리다이렉션**: `_git_env()` 가 상속된 `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` 을 제거한다 — 이 값들이 남아 있으면 git 작업이 **실제 프로젝트 저장소로 리다이렉트**될 수 있다. 신원은 `-c` 인자와 환경변수 양쪽에 주입하며 `git config --global` 은 건드리지 않는다. `commit --no-verify`·`add --force` 는 사용자 전역 훅·excludesFile 이 생성물에 영향을 주지 않게 하려는 것으로, 대상이 gitignore 된 일회성 fixture repo 에 한정된다.
- **원본 repo 무변경 (CLAUDE.md CRITICAL)**: 빌더는 `evaluation/fixtures/replay_repos/` 하위에서만 `git init`·commit·tag 한다. 프로젝트 저장소나 `mock_repo/` 에 커밋·태그·checkout·reset 을 수행하는 코드 없음. 빌드 후 `git status` clean 확인.
- **코드 반출 금지 (CLAUDE.md CRITICAL)**:
  - 로더가 `os.environ`/`os.getenv` 를 **호출하지 않는다**(grep 0건) — `path_env` 는 이름만 담고 값 해석은 #0018 몫이라, 로드 시점에 회사 절대경로가 메모리·오류 메시지에 실리지 않는다.
  - `company_replay.template.yaml` 에 실제 절대경로·commit SHA·코드 본문 없음 — `path_env: "EHR_REPO_ROOT"`, revision 은 `REPLACE_WITH_*_REVISION` placeholder, `privacy_mode: metadata_only` 기본. 이를 고정하는 회귀 테스트가 `tests/test_replay_fixtures.py` 에 있다.
  - `PrivacyMode` 허용 집합은 **화이트리스트**다(`_ALLOWED_ARTIFACTS`). 새 artifact 종류를 표에 넣는 것을 잊으면 저장이 막힐 뿐 유출되지 않는다. `METADATA_ONLY` 가 `ReplayExecution` 기본값이라 fixture 가 모드를 생략해도 가장 엄격한 쪽으로 떨어진다. 미지의 `privacy_mode` 값도 오류를 쌓은 뒤 `METADATA_ONLY` 로 처리한다.
  - `GOLDEN_OUTPUT` 을 별도 artifact 종류로 분리해 `FULL` 에서만 허용한다 — 골든 테스트 스택트레이스에 코드가 실려 나오는 경로를 막는다.
- **역직렬화**: `yaml.safe_load` 만 사용(`yaml.load` 0건). root 가 dict/list 가 아니거나 구조가 어긋나면 `DatasetValidationError`.
- **커밋된 fixture 내용**: `replay_sources/**` 는 `com.example.*` 패키지의 합성 Java 로, 실제 eHR 경로·암호 컬럼코드·내부 파생물을 포함하지 않는다. 시크릿 패턴(password/secret/token/api_key) 검색 0건. "연금계좌"는 소득세법 제59조의3 조문 인용으로 실제 계좌번호가 아니다.
- **gitignore**: `evaluation/fixtures/replay_repos/` 추가로 생성된 git repo 가 추적되지 않음(빌드 후 `git status` clean 확인). `replay_sources/`·`replay/mock_cases.yaml` 은 의도대로 커밋 대상.
- **인증/인가**: 신규 엔드포인트·라우트 0건. FastAPI·DB 를 건드리지 않는다(평가 계층은 서버 기동과 무관).
- **개인정보·로그**: 이번 diff 에 `logging`/`logger` 추가 0건. 빌더의 `print` 는 빌드된 상대 경로만 출력한다. 개인정보를 다루는 경로 없음.
- **설정/TLS**: 하드코딩 시크릿·커밋된 `.env` 없음. 신규 설정 항목 0건. CORS·쿠키 플래그·디버그 모드·TLS 무력화(`verify=False`, `NODE_TLS_REJECT_UNAUTHORIZED`) 변경 0건.
- **의존성**: `requirements.txt`/`requirements-dev.txt` 무변경.

## 점검 불가

- **#0018 runner 의 실제 실행 안전성**: worktree 생성·golden 실행·cleanup 은 아직 구현되지 않았다. 발견 #1(인자 미검증)의 실질 위험도 runner 구현 후에야 확정할 수 있다.
- **회사 환경 fixture**: 실데이터 fixture 는 `evaluation/private/`(gitignore)에 사용자가 회사에서 작성한다. 그 내용의 반출 위험은 이 저장소에서 점검할 수 없다 — 템플릿 주석과 `metadata_only` 기본값이 방어선이다.

## 수용된 리스크 (사용자 확인 필요)

- **#1 `golden_command` 인자 미검증 (Low)**: 현재 mock fixture 가 `golden_command` 를 쓰지 않아 노출이 없고, 완화 지점이 실행 계층(#0018)이라 그쪽으로 넘긴다. **#0018 설계 시 반드시 다룰 것** — 임시 worktree cwd 고정 + 절대경로 인자·`-f`/`-p` 계열 옵션 차단.
- **허용 도구가 대상 repo 코드를 실행하는 것**: `mvn`/`gradle`/`pytest` 는 replay 대상 repo 안의 빌드 스크립트·conftest 를 실행한다. 이는 "과거 시점 코드에서 골든 테스트를 돌린다"는 기능의 본질이며, **replay 대상 repo 를 신뢰한다**는 전제 위에서 수용한다. fixture YAML 문자열을 실행하던 채널(`bash -c`)은 위 "수정 완료"로 제거됐다.
